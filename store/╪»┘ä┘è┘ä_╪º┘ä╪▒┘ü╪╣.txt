===========================================================
  دليل الرفع على
  GitHub
  ثم التشغيل على استضافة
===========================================================

الملفات المطلوبة للنشر موجودة كلها داخل الأرشيف، ولا تحتاج تعديل
أي سطر برمجي.


-----------------------------------------------------------
الجزء الأول: الرفع على
GitHub
-----------------------------------------------------------

الطريقة الأسهل (بدون أوامر):

  1. افتح
     github.com/new

  2. اكتب اسم المستودع، مثال:
     ghanima-store

  3. اختر
     Private
     لأن المشروع سيحتوي لاحقًا على مفاتيح دفع.

  4. لا تضع علامة على
     Add a README
     ولا على
     Add .gitignore
     لأنهما موجودان أصلًا.

  5. اضغط
     Create repository

  6. في الصفحة التالية اضغط
     uploading an existing file

  7. فك الأرشيف على جهازك، ثم اسحب محتويات مجلد
     store
     كلها إلى الصفحة. مهم: اسحب المحتويات نفسها، لا المجلد.

  8. اضغط
     Commit changes


الطريقة الثانية (بالأوامر):

    cd store
    git init
    git add .
    git commit -m "أول نسخة من المتجر"
    git branch -M main
    git remote add origin https://github.com/USERNAME/ghanima-store.git
    git push -u origin main

استبدل
USERNAME
باسم حسابك.


تنبيه مهم قبل الرفع:

  ملف
  .gitignore
  يمنع رفع مجلد
  data
  وهذا مقصود. المجلد يحتوي قاعدة البيانات ومفتاح الجلسات
  secret.key
  ولا يجب أن يصل إلى
  GitHub
  إطلاقًا.

  ولا تكتب مفاتيح
  Stripe
  أو
  PayPal
  داخل أي ملف. تُدخل من لوحة تحكم المتجر أو من متغيرات الاستضافة.


-----------------------------------------------------------
الجزء الثاني: التشغيل من
GitHub
على استضافة
-----------------------------------------------------------

المتجر يحفظ بياناته في ملف على القرص، لذلك تحتاج استضافة تدعم قرصًا
دائمًا
Persistent Disk
وإلا ستُفقد الطلبات والمنتجات عند كل إعادة نشر. هذه أفضل ثلاثة
خيارات:


الخيار الأول:
Railway
— الأسهل والأنسب لك

  1. ادخل
     railway.com
     وسجّل بحساب
     GitHub

  2. اضغط
     New Project
     ثم
     Deploy from GitHub repo
     واختر المستودع.

  3. سيكتشف
     Node.js
     تلقائيًا ويشغّل
     node server.js
     بفضل ملف
     railway.json
     الموجود في المشروع.

  4. من تبويب
     Variables
     أضف:

         DATA_DIR = /data
         SECURE_COOKIES = 1
         ADMIN_USER = اسم المستخدم الذي تريده
         ADMIN_PASS = كلمة مرور قوية

  5. من تبويب
     Volumes
     أنشئ قرصًا وثبّته على المسار
     /data
     هذه الخطوة إلزامية، لا تتجاوزها.

  6. من تبويب
     Settings
     اضغط
     Generate Domain
     ثم انسخ الرابط وأضفه كمتغير:

         BASE_URL = https://your-app.up.railway.app

  7. أعد النشر، ثم افتح الرابط. لوحة التحكم على المسار
     /admin


الخيار الثاني:
Render

  1. ادخل
     render.com
     ثم
     New
     ثم
     Web Service
     واختر المستودع.

  2. المشروع يحتوي ملف
     render.yaml
     جاهزًا، فيقرأ الإعدادات منه تلقائيًا.

  3. اضبط:

         Build Command  = اتركه فارغًا
         Start Command  = node server.js

  4. أضف قرصًا
     Disk
     على المسار
     /var/data
     وحجم واحد
     GB
     يكفي طويلًا.

  5. أضف المتغيرات:

         DATA_DIR = /var/data
         SECURE_COOKIES = 1
         BASE_URL = https://your-app.onrender.com
         ADMIN_USER
         ADMIN_PASS

  ملاحظة: القرص الدائم في
  Render
  يحتاج خطة مدفوعة. الخطة المجانية تمسح البيانات عند كل نشر، فلا
  تستخدمها للمتجر الحقيقي.


الخيار الثالث: سيرفر خاص
VPS
مع
Docker

  المشروع يحتوي ملف
  Dockerfile
  جاهزًا:

      git clone https://github.com/USERNAME/ghanima-store.git
      cd ghanima-store
      docker build -t ghanima .
      docker run -d --name ghanima \
        -p 3000:3000 \
        -v /srv/ghanima-data:/data \
        -e SECURE_COOKIES=1 \
        -e BASE_URL=https://yourdomain.com \
        -e ADMIN_USER=owner \
        -e ADMIN_PASS=StrongPass123 \
        --restart unless-stopped \
        ghanima

  ثم مرّر النطاق إليه عبر
  Nginx
  وفعّل شهادة
  SSL
  بواسطة
  certbot
  كما في دليل التركيب.


-----------------------------------------------------------
الجزء الثالث: بعد أول نشر
-----------------------------------------------------------

  1. افتح سجل الاستضافة
     Logs
     وستجد كلمة مرور لوحة التحكم مطبوعة مرة واحدة — إن لم تكن قد
     ضبطت
     ADMIN_PASS
     مسبقًا.

  2. ادخل
     /admin
     وغيّر كلمة المرور من صفحة الإعدادات.

  3. اكتب بيانات حسابك البنكي، وفعّل بوابة الدفع التي تريدها.

  4. احذف المنتجات التجريبية الستة وأضف منتجاتك.

  5. جرّب طلبًا حقيقيًا بمبلغ صغير قبل الإعلان عن المتجر.


-----------------------------------------------------------
الجزء الرابع: تحديث المتجر لاحقًا
-----------------------------------------------------------

عدّل الملفات على جهازك ثم:

    git add .
    git commit -m "وصف التعديل"
    git push

الاستضافة تعيد النشر تلقائيًا. بياناتك لا تُمس، لأنها على القرص
الدائم وليست داخل المستودع.


-----------------------------------------------------------
جدول المتغيرات كاملًا
-----------------------------------------------------------

    PORT             منفذ التشغيل، الافتراضي 3000
    DATA_DIR         مسار القرص الدائم للبيانات
    BASE_URL         رابط موقعك الكامل مع
                     https
    SECURE_COOKIES   اجعله 1 عند استخدام
                     https
    ADMIN_USER       اسم مستخدم اللوحة عند أول تشغيل
    ADMIN_PASS       كلمة مروره عند أول تشغيل
